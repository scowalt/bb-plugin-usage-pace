# Usage Pace 0.4.5

Patch release for a quieter usage dialog and clearer reset status.

## Changes

- **Quota details first.** Removed the token-total card and its explanatory text. The UI no longer fetches or polls token totals; `bb usage-pace --tokens` and the token RPC remain available.
- **Only relevant accounts.** The strip, dialog, pools, and reset-read targets share an account filter. Uninstalled providers and discoveries without quota windows, account identity, or a previous reading stay hidden. This removes unused Cursor/OpenCode entries without hiding real accounts whose reads fail or logins expire. Known accounts without quota windows keep their reset details and never claim their quota will last.
- **Compact header.** Title, update time, and refresh share one row. Mobile safe-area padding and accessible dialog behavior are preserved.
- **Clearer reset status.** Conditional five-hour availability shows the provider-reported reason directly, such as “Not available · session limit not reached.” Removed duplicate zero-balance copy, repeated disclaimers, and nested reset cards. Saved balances, expirations, unknown states, and conditional availability remain distinct.

This does not change provider eligibility or redeem any resets. The read-only live check for the reported Claude account returned zero saved resets and `not_at_wall`; no missing grant was reproduced. Raw CLI account output remains available for diagnosis.

Minimum requirements and dependency pins are unchanged: **BB 0.44.0 / SDK 0.5.29**.

## Verification

- 425 Vitest tests and 3 token-total tests pass, including before/after regressions for unused providers, known-account failures, token polling, and reset explanations.
- Type checking, comment-policy checks, and production-only rebuild/runtime smoke checks pass. Release artifacts use BB 0.44.0 / SDK 0.5.29.
- Synthetic browser checks at 1200px, 375px, and 320px confirm no horizontal overflow or token requests. Header height falls from 40.75px to 24.5px in the component fixture. Refresh, Escape/reopen, empty/stale accounts, and available/unknown reset states pass without browser errors.
- The browser fixture uses production components and generated CSS with synthetic accounts/RPC and placeholder provider marks. It is not a live installation or native desktop acceptance test.

## Install or upgrade

For a new installation:

```sh
bb plugin install 'git:https://github.com/scowalt/bb-plugin-usage-pace.git@v0.4.5'
bb plugin config usage-pace set showStrip true
```

Reload the app UI to show the optional footer card. Use `@^0.4.5` instead of the exact tag to track compatible releases.

For an existing installation, inspect its source first:

```sh
bb plugin source usage-pace
```

Branch-tracking and compatible release-range installs can update while preserving settings:

```sh
bb plugin update usage-pace
```

Exact tags and commits remain pinned. Changing a pinned source may require removal and reinstall; **removal deletes settings, secrets, and schedules**, so record the configuration first. See [upgrade instructions](https://github.com/scowalt/bb-plugin-usage-pace/blob/v0.4.5/README.md#upgrades).

Publishing this release does not install, update, reload, or reconfigure any live plugin.
