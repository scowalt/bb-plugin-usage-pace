# Usage Pace 0.4.9

Patch release that makes Claude's limit-reset details compact and says what each reset clears.

## Changes

- **One row per reset.** Each Claude reset used to take five lines: a generic heading such as **Other saved reset · 1 saved**, the grant label, an **Affects** line, a countdown, and the full expiry date. Each reset is now one row. The row shows the grant's own name, a short countdown such as `27d`, and a line that holds what the reset clears and the expiry date. A leading clause such as `New model launch:` is dropped from the name, and the full label stays in the tooltip. The full expiry time is in the countdown's tooltip. The countdown turns amber within seven days and reads `Expired` after the expiry passes. `×N` appears only when a grant has more than one use.
- **What a reset clears, with its usage.** The row says `Clears weekly · 69% used`. The percentage is the usage that Claude reported for that grant. A grant that clears only an unrecognized weekly meter, such as Claude's undocumented `seven_day_overage_included`, says `Clears a second weekly meter`. Before, it said `weekly included usage`, which implied a meaning that nobody has confirmed. Hover the tag to see Claude's raw meter names and percentages.
- **Compact 5-hour reset.** The conditional 5-hour reset is one line: the label on the left and the status on the right.
- Codex banked resets use the same row. Codex reports no meters, so the second line shows only the date.

Minimum requirements are unchanged: **BB 0.48.1 / SDK 0.6.104**.

## Verification

- New tests cover the clears tags and percentages, the raw-meter tooltip, the shortened names, the amber and `Expired` countdown states, a grant that clears several unrecognized meters, an unreported Codex expiry, and a malformed `percent_used` value. A malformed value drops only that grant's percentage and keeps the inventory. This test fails without the fallback.
- Type checking, 452 Vitest tests, 3 token-total tests, and comment-policy checks pass.
- The real component was rendered with the built stylesheet and live account data in headless Chromium.
- Built with BB 0.48.1. `check:release` passes, including the isolated production-only rebuild.

## Install or upgrade

For a new installation:

```sh
bb plugin install 'git:https://github.com/scowalt/bb-plugin-usage-pace.git@v0.4.9'
bb plugin config usage-pace set showStrip true
```

Reload the app UI to show the optional footer card. Use `@^0.4.9` instead of the exact tag to track compatible releases.

For an existing installation, inspect its source first:

```sh
bb plugin source usage-pace
```

Branch-tracking and compatible release-range installs can update while preserving settings:

```sh
bb plugin update usage-pace
```

Exact tags and commits remain pinned. Changing a pinned source may require removal and reinstall; **removal deletes settings, secrets, and schedules**, so record the configuration first. See [upgrade instructions](https://github.com/scowalt/bb-plugin-usage-pace/blob/v0.4.9/README.md#upgrades).

Publishing this release does not install, update, reload, or reconfigure any live plugin.
