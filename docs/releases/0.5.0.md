# Usage Pace 0.5.0

Minor release that can pick the model and effort of every new thread.

## Changes

- **Model autopilot.** On a bb with the new-thread chooser, Usage Pace chooses Opus or Gemini Neon for each new thread that names no model, and sets its effort from the overall pace. A composer thread whose model a person or plugin named keeps it, and a spawn that names only an effort keeps that effort, lowered to a level the chosen model has. The overall pace leaves out a subscription skipped for the thread, so an Opus thread on a machine without Antigravity follows Claude's pace alone. The lower weekly pace wins, a tie or unknown usage goes to Opus, and a subscription at 85% on its 5-hour window or 90% weekly is skipped. Gemini Neon is also skipped on a machine where it cannot start. See [Model autopilot](../../README.md#model-autopilot).
- **New settings.** `autopilot` (on by default) and `autopilotEffortBands` (default `0.7=max,0.9=xhigh,1.0=high,1.2=medium,low`).
- **New command.** `bb usage-pace autopilot [--json] [--host <id>]` prints the model and effort a new thread would get now, and why.

On a bb without the chooser, autopilot does nothing and the command says so. Minimum requirements are unchanged: **BB 0.48.1 / SDK 0.6.104**.

## Verification

- Unit tests cover the model choice, the skip gates, the early-window pace, the effort bands and their parsing, the requests autopilot covers (including named models and efforts), the skipped-subscription effort pace, the machine check, and the cold-cache budget. Server tests cover registration and the command.
- Type checking, 598 Vitest tests and 3 token-total tests pass.
- Before tagging, rebuild `dist/` with a released bb. A fork build such as `0.50.2-fork.23` fails `check:release`, which wants an exact version.
