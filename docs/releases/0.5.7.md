# Usage Pace 0.5.7

Patch release that stops autopilot from assigning `max` effort to new threads right after a usage reset.

## Changes

- **Early-window resets no longer drive effort to `max`.** When a weekly window has just reset (`< 5%` elapsed and `< 5%` used), `weeklyPace()` floors elapsed time at 5% so model selection still prefers the freshly reset subscription. Those early windows are now excluded from `subPaces` when computing overall effort: if all available subscriptions just reset, autopilot uses `high` (`UNKNOWN_EFFORT`) until either 5% of the week has elapsed or 5% of quota is used; if only one subscription reset, effort follows the remaining mid-week subscriptions instead of being dragged down by `0.00×`.

Minimum requirements are unchanged: **BB 0.48.1 / SDK 0.6.104**.

## Verification
