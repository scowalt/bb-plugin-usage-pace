# Usage Pace 0.4.1 — draft release notes

Patch release for issues found during the 0.4.0 live check on bb 0.46.1 / SDK 0.6.49 with two Claude Accounts logins.

## Fixes

1. **Healthy server accounts stay visible.** An account usage error, rejected resource read, or failed source inventory no longer marks an entire host unavailable. Server-only filtering only treats host identity, availability, and host-list failures as server failures.
2. **Account errors stay on their rows.** The dialog footer and CLI warning no longer repeat individual account errors. Discovery, host-list, and source-list failures still produce collection warnings.
3. **Card errors stay on the failed tab.** Recognizes all three bb 0.46.1 notices, including “Couldn’t refresh. Showing last update.”, while retaining older wording. Healthy Codex, Claude Code, and All accounts tabs stay clear when the failed provider is known.
4. **Merged accounts show the right location.** Strip descriptions and dialog locations use the server machine in server-only mode and all associated machines otherwise. Saved-reset details name the machine that actually supplied the verified inventory.
5. **No repeated provider labels.** CLI, strip, and dialog omit fallback account labels that equal the provider display name, ignoring case. Meaningful account labels and aliases remain.
6. **Separate installation and upgrade instructions.** Inspect the source before choosing an in-place update or a settings-destructive remove/reinstall.
7. **Transient keyless errors do not split known accounts.** A resource that previously reported an account key keeps it when an error omits the key, so a sleeping laptop does not add a phantom pool member. Never-known identities remain separate; a successful login change replaces the key.

Release artifacts remain built with BB 0.44.0 / SDK 0.5.29. Minimum requirements are unchanged. Saved resets remain read-only; the CLI JSON accounts/providers alias, nullable pace, token totals, and Codex-only `--resets` behavior are unchanged.

## New installations

After 0.4.1 is published:

```sh
bb plugin install 'git:https://github.com/scowalt/bb-plugin-usage-pace.git@v0.4.1'
bb plugin config usage-pace set showStrip true
```

The second command enables the optional strip. Use `@^0.4.1` instead of the exact tag to track compatible releases.

## Upgrades

Inspect the requested and resolved source first:

```sh
bb plugin source usage-pace
```

For repository/branch-tracking installs whose branch contains 0.4.1, or a release-range install that admits the published tag, update in place and keep settings:

```sh
bb plugin update usage-pace
```

An exact tag or commit does not advance to a newer tag with `update`. Moving a pinned install, or changing an existing install to a tag or range, requires removal first. **Removal deletes settings, secrets, and schedules.** Record the current configuration and restore your settings after reinstalling:

```sh
bb plugin config usage-pace
bb plugin remove usage-pace
bb plugin install 'git:https://github.com/scowalt/bb-plugin-usage-pace.git@v0.4.1'
```

Use `@^0.4.1` in the final command for compatible-release tracking. Do not use `plugin install` as an in-place upgrade: bb 0.46.1 rejects the duplicate plugin ID.
