# Usage Pace 0.4.6

Patch release that keeps Claude Code and Codex usage visible when bb's own providers are disabled, and stops a freshly reset window from reading as unknown.

## Changes

- **Claude Code and Codex without bb's provider.** Disabling bb's `claude-code` or `codex` provider empties its usage source, so those accounts disappeared from Usage Pace. Usage Pace now serves its own source for each connected machine where bb lists no usage-reporting provider of that kind. The host entry reads the local Claude Code or Codex login and requests the same session, weekly, and per-model windows bb's provider would. Machines where bb's provider is enabled are skipped, and accounts merge by the same provider-issued `accountKey`, so nothing is counted twice. Readings are cached for five minutes; read failures stay errors and never become zero usage.
- **“other pace unknown” only for unknown pace.** A hidden window that is merely too early to judge, such as an OpenCode Go monthly window that just reset, no longer triggers the notice. Hidden windows without a reset time still do.
- The Grok Build source now shares one `provider-usage.v1` registration with the new source; its resources and behavior are unchanged.
- **SDK repinned to the running bb.** `bb plugin build` stamps the SDK of the bb that builds it, and `check:release` required that stamp to equal the pinned SDK 0.5.29. Only an old BB 0.44.0 toolchain could pass, and running its launcher through `BB_CLI` recursed until the build host ran out of memory. `@get-bb/plugin-sdk` is now pinned to 0.6.104 (it stays a production dependency for the Grok host bridge), which brings zod 4.6.5.
- **Release check compares against the build stamp.** `check:release` no longer requires one exact bb. All three bundles must carry the same build stamp, the stamped bb and SDK must satisfy `engines`, and the pinned SDK must satisfy `engines.bbPluginSdk`. The development notes now warn against overriding `BB_CLI` or running older bb launchers.

Minimum requirements are raised to match the build toolchain: **BB 0.48.1 / SDK 0.6.104**.

## Verification

- Vitest covers both readers (windows, plans, account keys, signed-out, expired, API-key, HTTP 401/429/5xx, malformed and network failures), the fallback source (host filtering, caching, failure retention, ownership), host routing, an end-to-end `getUsage` with bb's providers absent, and the hidden-early-window regression.
- Type checking, 446 Vitest tests, 3 token-total tests, and comment-policy checks pass on SDK 0.6.104.
- Built with the installed BB 0.48.1. `check:release` passes with that bb's bundled npm 11.16.0, including the isolated production-only rebuild. It confirms both new host reads report a signed-out state in an isolated home without contacting providers. A bundle stamped by a different bb is rejected.
- A read-only live run of both readers on the server host returned `ok` Claude Pro and Codex Pro windows. `bb provider list` confirmed the disabled providers are absent, so the fallback applies there.

## Install or upgrade

For a new installation:

```sh
bb plugin install 'git:https://github.com/scowalt/bb-plugin-usage-pace.git@v0.4.6'
bb plugin config usage-pace set showStrip true
```

Reload the app UI to show the optional footer card. Use `@^0.4.6` instead of the exact tag to track compatible releases.

For an existing installation, inspect its source first:

```sh
bb plugin source usage-pace
```

Branch-tracking and compatible release-range installs can update while preserving settings:

```sh
bb plugin update usage-pace
```

Exact tags and commits remain pinned. Changing a pinned source may require removal and reinstall; **removal deletes settings, secrets, and schedules**, so record the configuration first. See [upgrade instructions](https://github.com/scowalt/bb-plugin-usage-pace/blob/v0.4.6/README.md#upgrades).

Publishing this release does not install, update, reload, or reconfigure any live plugin.
