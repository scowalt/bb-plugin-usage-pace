---
name: usage-pace
description: Check provider quota, burn-rate pace, read-only Codex/Claude saved-reset status, and which model autopilot gives a new thread.
---

Run `bb usage-pace` for weekly windows grouped by provider, with the pool before its accounts. `--all --force` refreshes every window from all discovered `provider-usage.v1` sources. `--json` returns `accounts[]`, `pools[]`, and a `pace` object on each window (`ratio`, `projectedPercent`, `runsOutAtMs`, `lockoutMs`, `budgetPerHour`). `providers[]` is a deprecated alias of `accounts[]` through 0.4.x. Identify accounts by `accountKey`, not email; null identities stay separate. Unknown/stale pace is null. Pools are plan-weighted weekly estimates, may be partial, and have no run-out forecast. `--tokens` gives recorded token totals. Grok Build is provider `usage-pace-grok`. Google Antigravity is provider `usage-pace-antigravity`. It lists only on machines where `agy` is installed and reads quota with `agy -p /usage --output-format json`. Its windows are `<group> · 5h` and `<group> · Weekly`. A signed-out agy is `unauthenticated`, a missing one is `not_installed`, and a failed read is an error, never 0%. It reports no account or plan. Another plugin reads it with `bb.sdk.system.usageLimits({ hostId, providerId: "usage-pace-antigravity" })`. That read is cached for up to five minutes, but bb stops the idle bridge after a minute, so a call after a quiet minute runs `agy` again (about 2-5 s, or an error after about 15 s if agy hangs). The `antigravityUsage` setting turns it off.

Run `bb usage-pace autopilot [--json] [--host <id>]` to see the model and effort a new thread would get now, and why. Autopilot picks Opus (`pi`) or Gemini Neon (`usage-pace-antigravity`, the plugin's own Antigravity provider) for threads that name no model (a composer thread keeps a model a person or plugin named; a spawn that names only an effort keeps that effort, clamped to the chosen model): the lower weekly pace wins, a tie or unknown goes to Opus, and a subscription at 85% on its 5-hour window or 90% weekly is skipped. Gemini Neon is also skipped on a machine where it cannot start. Effort follows the mean of the paces of the subscriptions that were not skipped for the thread (`autopilotEffortBands`, default `0.7=max,0.9=xhigh,1.0=high,1.2=medium,low`; unknown is high; Gemini Neon tops out at xhigh). The `autopilot` setting turns it off. It needs a bb with the new-thread chooser; the command says when nothing uses its choice.

The compact strip and dialog show read-only Codex/Claude saved-reset counts and expirations. Claude's conditional five-hour availability is separate from that count; its next-availability time is not an expiry. Missing inventory means unknown, not zero. A badge appears only after the host login's provider-issued identity matches the quota account; a verified failed read shows `↺ ?`, and an unread or mismatched inventory has no badge. Reads use the default login on an available BB host; shared-source accounts need a matching host login for reset details. The server/UI machine does not need a subscription. No resets are redeemed and credentials stay on the host.

`bb usage-pace --resets --json` retains its Codex-only inventory on the primary host; it does not report Claude resets. Claude's inventory is currently available in the strip/dialog.

For a server-only strip/dialog, run `bb plugin config usage-pace set serverOnly true` (off by default, shared across browsers, no reload needed). Machine-scoped accounts must be available on the server, while shared-scope accounts stay visible. Reset reads stay on the server host. This is a UI filter; the Provider Usage card, CLI, and token totals remain global. Configure aliases with `accountAliases` (`email=Alias`) and estimated pool weights with `poolWeights` (`email=weight`), using comma/newline-separated pairs. See [server-only view](../../README.md#server-only-view) for host selection, empty states, and reset-read scope.
